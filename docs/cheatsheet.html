Что нужно помнить про историю

пробел в начале
команда, набранная с ведущим пробелом, в историю не попадёт. Так вводят строки с паролями и токенами
где лежит
~/.local/state/zsh/history, а не в репозитории: иначе токены из командной строки уехали бы в git
общая
все вкладки пишут в один файл и сразу видят команды друг друга
секреты
внутренние хосты, строки подключения и токены — в ~/.config/zsh/local.zsh, он вне git

Секреты

Пароли БД, токены, ключи и kubeconfig лежат в отдельном keychain dev, а не в Apple Passwords: у Passwords нет API. Команда sec прячет длинные вызовы security.

Положить

sec add имя
спросит значение скрытым вводом, на экране ничего не появится
-a · -n
аккаунт или логин · заметка: хост, порт, для чего
-f файл
сохранить файл целиком: ключ, kubeconfig, сертификат
-u
заменить существующую запись
из пайпа
printf '%s' токен | sec add kafka/token

Имена через слэш группируются: ssh/id_work, k8s/prod. Группы видны в sec ls и в автодополнении по Tab.

Достать

sec get имя
в stdout, чтобы подставить: $(sec get pg-staging)
sec cp имя · sc
в буфер обмена, очистится через 30 секунд
sec out имя путь
восстановить файл на диск с правами 600
sec ls
список записей без самих секретов, можно с префиксом
sec show имя
метаданные: аккаунт, заметка, когда создана
sec rm имя
удалить, -y без подтверждения

Запустить команду с секретами в окружении

sec env -- команда
читает .secrets из текущего каталога и подставляет значения только этой команде
-f путь
взять другой файл: sec env -f ops/.secrets -- kubectl get pods
формат файла
строки вида PGPASSWORD=pg-staging: слева переменная, справа имя записи
в git
.secrets можно коммитить — в нём только имена, самих секретов нет
в шелл
ничего не экспортируется: переменные живут только внутри запущенной команды

Первый запуск и обслуживание

sec init
один раз: создать keychain и задать пароль
sec doctor
проверить всё: keychain, таймаут, age, fzf, jq
sec lock / unlock
заблокировать и разблокировать вручную
sec help команда
подробная справка с примерами по каждой команде
make test
прогнать тесты sec на временном keychain, ваши записи не трогает

Переезд на другую машину

sec export
все записи в файл dev-secrets-ДАТА.age, зашифрованный парольной фразой
sec import файл
загрузить на новой машине, после sec init
--json
открытый JSON в stdout, для переезда в другой менеджер паролейбез шифрования
вручную
скопировать dev.keychain-db и выполнить sec init --attach

Парольную фразу от экспорта храните в Apple Passwords. Сам файл .age можно держать хоть в iCloud Drive.

macOS

Системные настройки и приложения тоже описаны в репозитории: новая машина настраивается теми же командами.

Что меняет make macos

клавиатура
быстрый автоповтор, долгое нажатие повторяет букву, без автозамены кавычек, тире и заглавных, Tab ходит по всем кнопкам диалогов
Finder
видны расширения и скрытые файлы, путь в заголовке и внизу окна, вид списком, поиск в текущей папке
скриншоты
в ~/Pictures/Screenshots, PNG, без тени
Dock
прячется без задержки, без недавних приложений, значки 48 точек
прочее
новые документы сохраняются на диск, а не в iCloud; нет вопроса «скачано из интернета»; .DS_Store не пишется на флешки и сетевые диски

Каждая настройка обратима: поменять значение в macos/defaults.sh и запустить снова.

Quick Look для Markdown

Space в Finder
показывает отрендеренный .md, а не простыню текста

Настройки правятся в самом приложении QLMarkdown. Оно в песочнице, поэтому его plist лежит в групповом контейнере — руками туда лезть не надо, есть make ql-save.
