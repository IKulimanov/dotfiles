Как работать с кластером из консоли

От «открыл терминал» до «посмотрел логи и перезапустил сервис». Все команды здесь — рабочие: алиасы лежат в ~/dotfiles/zsh/.config/zsh/conf.d/40-k8s.zsh.

Как подключиться

Отдельно «подключаться» не нужно — нет команды логина, после которой ты «внутри». Просто набираешь команду, и если сессия протухла, тебя сами отправят в браузер. Вот как это выглядит в первый раз за день.

1

Проверь, что ты в рабочей сети

Кластеры внутренние, из интернета не видны. Нужен офисный Wi-Fi или VPN. Если сети нет — команды отвалятся по таймауту.

2

Посмотри, в каком ты кластере

Контекст всегда виден в промпте, слева от строки ввода:

staging.nurtelecom.k8s PROD:nur-prod billing.nurtelecom.k8s

Зелёный — staging, работай спокойно. Красный — прод. Жёлтый — кластер, по имени которого не понять, что за среда; считай его продом.

3

Набери любую команду

Самая простая — показать поды:

kgp

Если сессия ещё жива, сразу появится список. Если протухла — увидишь строку про запуск браузера, и откроется вкладка Keycloak.

4

Войди в браузере

Логин и пароль — рабочие, те же что от корпоративных систем. После входа в браузере напишет Authenticated, вкладку можно закрыть. Возвращайся в терминал — команда выполнится сама.

kgp Open Launching a browser... # ...входишь в браузере, возвращаешься сюда... NAME READY STATUS RESTARTS AGE business-m2m-gateway-incident-85b5dcb956-xf9mb 1/1 Running 0 36d business-m2m-gateway-kpi-7d9ddccb4b-4k97x 1/1 Running 1 36d business-m2m-gateway-tb-7d56dd5957-mh2k8 1/1 Running 0 36d

Дальше токен обновляется в фоне сам. Логин в браузере понадобится снова только после долгого перерыва.

Проверить, кто ты

kubectl auth whoami покажет, под какой учёткой ты зашёл и в какой группе состоишь. kubectl auth can-i --list — что тебе здесь разрешено.

Где я сейчас и как переключиться

Два уровня: кластер (он же контекст) и namespace внутри него. Почти все команды работают в текущем namespace — если ошибиться, получишь «access denied».

kctxсменить кластер — без аргумента откроется список
knsсменить namespace — тоже списком, ищется по буквам
kubectl config get-contextsвсе кластеры и их namespace таблицей
kubectl auth whoamiкем ты видишься кластеру

Namespace, где у тебя есть права

staging-business-m2m-gateway открывается по умолчанию
staging-apps-monitoring-service
staging-cockpit-testing-management
staging-education
staging-myo-flow-event

Остальные 78 namespace кластера видны в списках, но внутри всё закрыто. В своих права полные: логи, вход внутрь пода, рестарт, удаление.

Посмотреть, что происходит

kgpподы: готовность, статус, сколько раз перезапускались, возраст
kgpwто же плюс нода и IP
kgdдеплойменты: сколько реплик поднято из скольких нужно
kgsсервисы и порты
ktopCPU и память по подам
kevсобытия кластера по времени — сюда смотреть, когда под не поднялся
kd pod <имя>подробности пода: образ, лимиты, причина падения
Как читать вывод kgp

READY 1/1 — контейнер поднят и прошёл проверку. RESTARTS больше нуля — под падал, смотри klp (лог прошлого запуска). STATUS кроме Running — kev объяснит причину.

Логи одного пода

klf <под>следить за логом вживую, последние 200 строк
kl <под>просто вывести лог и выйти
klp <под>лог предыдущего запуска — когда под упал и поднялся заново
kl <под> --since=1hтолько за последний час

Имя пода набирать целиком не обязательно — есть автодополнение по Tab.

Выйти из слежения

Ctrl + C. Работает и для klf, и для stern ниже.

Логи сразу с нескольких подов

kubectl logs умеет только один под. Когда у сервиса несколько реплик или надо следить за группой сервисов — это stern. Он держит все потоки разом, красит каждый под своим цветом и не отваливается, когда под пересоздают.

sl business-m2m-gateway + business-m2m-gateway-tb-7d56dd5957-mh2k8 › business-m2m-gateway-tb + business-m2m-gateway-kpi-7d9ddccb4b-4k97x › business-m2m-gateway-kpi + business-m2m-gateway-incident-85b5dcb956-xf9mb › business-m2m-gateway-incident # дальше идут строки логов, перед каждой — имя пода своим цветом
sl gatewayвсе поды, в имени которых есть «gateway»
sl deploy/my-serviceвсе поды одного деплоймента
sls app=my-serviceпо метке, а не по имени
sl gateway -s 15mначиная с событий 15-минутной давности
sl gateway --no-followвывести и выйти, без слежения
sl gateway -i ERRORтолько строки со словом ERROR
sl gateway -E healthcheckнаоборот, спрятать строки с healthcheck
sl . -n staging-educationвообще всё в другом namespace
Логи в формате JSON

Сервисы пишут ECS-логи одной длинной строкой. Чтобы читать глазами только текст сообщения: sl gateway -o raw | jq -r '.message'

Когда не помнишь имя пода

Три команды открывают список подов с поиском по буквам. Стрелки или продолжай печатать, Enter — выбрать, Esc — отменить.

klogвыбрать под → смотреть его логи вживую
ksshвыбрать под → зайти внутрь него
kdelвыбрать под → удалить, деплоймент поднимет новый

Справа в списке показывается описание выделенного пода, чтобы не выбрать не тот.

k9s — весь кластер в одном окне

Полноэкранный интерфейс, как lazygit, только для кластера. Удобен, когда надо не одну команду выполнить, а «посидеть и посмотреть»: что живо, что падает, открыть логи, перезапустить.

Как зайти и как выйти

k9s # откроется на подах текущего namespace k9s --readonly # без права что-либо менять — для чужого кластера k9s -n staging-education # сразу в нужном namespace

Выход — :q и Enter, либо Ctrl + C. Esc возвращает на шаг назад, не выходя из программы.

Что нажимать внутри

Команды начинаются с двоеточия — набираешь :, имя ресурса, Enter. Перемещение по списку — стрелки или j / k.

:poсписок подов — основной вид
:deployдеплойменты
:svcсервисы
:nsсменить namespace
:ctxсменить кластер
/отфильтровать список по тексту
Enterпровалиться внутрь выбранного
lлоги пода
Shift+Lлоги предыдущего запуска
dподробное описание
yпоказать yaml целиком
sоткрыть шелл внутри пода
Ctrl+Dудалить — спросит подтверждение
?все клавиши текущего вида
Настроено под чтение логов

Хвост поднят до 200 строк, длинные строки переносятся, у каждой показано время. Иначе JSON-логи и стектрейсы обрезаются на середине.

Перезапустить сервис

krr <deployment>rolling restart: реплики меняются по очереди, сервис не проседает
krs <deployment>следить, как идёт выкатка
krh <deployment>история выкаток
kdelвыбрать и убить один под — грубее, но быстрее
Имя деплоймента ≠ имя пода

У пода на конце хеш и случайный суффикс. Отбрось их:
под business-m2m-gateway-tb-7d56dd5957-mh2k8 → деплоймент business-m2m-gateway-tb.
Список деплойментов без угадывания — kgd.

Перед рестартом

Посмотри на цвет контекста в промпте. Красный и метка PROD: означают, что ты в проде и рестарт увидят пользователи.

Зайти внутрь пода и пробросить порт

ksshвыбрать под из списка и зайти внутрь
kex <под> -- shто же, если имя пода уже знаешь
kpf <под> 8080:8080порт пода доступен на localhost:8080
kpf svc/<сервис> 8080:80проброс на сервис, а не конкретный под

Выйти из пода — exit. Остановить проброс — Ctrl + C.

Если что-то не работает

error: You must be logged in to the server (Unauthorized) Сессия Keycloak истекла. Набери любую команду — откроется браузер, войди рабочей учёткой. Дальше всё продолжится само.
access denied for user on resource "":v1/pods in namespace "default" Ты в namespace, где у тебя нет прав. Переключись: kns — и выбери один из своих пяти (список выше).
Unable to connect to the server: dial tcp ... i/o timeout Нет доступа к внутренней сети. Проверь Wi-Fi или подключись к VPN.
command not found: k · command not found: sl Алиасы подхватываются при старте шелла. После правки конфига выполни exec zsh или открой новую вкладку терминала.
Lens: executable oidc-login not found Приложения из Dock не видят PATH терминала. Запускай Lens командой open -a Lens.
error: arguments in resource/name form must have a single resource and name Обычно это krr с именем пода вместо деплоймента. Посмотри правильные имена: kgd.
алиасы — ~/dotfiles/zsh/.config/zsh/conf.d/40-k8s.zsh настройки k9s — ~/dotfiles/k9s/.config/k9s/config.yaml доступы — ~/.kube/config, в git не хранятся
