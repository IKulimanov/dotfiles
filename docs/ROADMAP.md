# Роадмап

Этапы пересобраны под принятые решения. Исходный разбор — в [ANALYSIS.md](ANALYSIS.md).

Принятые рамки:

- **Java в nvim не нужна** — для неё IntelliJ IDEA. Neovim берёт на себя YAML/k8s,
  документацию, логи, Go и личные проекты.
- **Часть 4 (инструменты под стек) — не трогаем.** kubectl, k9s, kcat, psql,
  клиенты Oracle/ClickHouse, java- и go-тулинг в Brewfile не добавляются.
- **Личные данные не хранятся в репозитории** — спрашиваются при установке.

## Этап 1 — сделано

### Идентичности git

Имя и почта убраны из `git/.config/git/config`. `install.sh` создаёт
`~/.config/git/identity` (права 600, вне git) и спрашивает:

1. имя и личную почту — используются по умолчанию везде;
2. нужен ли дополнительный аккаунт, и **внутри какого каталога** он действует
   (по умолчанию `~/work/`) — вопрос повторяется, аккаунтов можно завести сколько угодно.

Работает через `includeIf "gitdir:…"`. Проверено: внутри `~/work/` git отдаёт рабочую
почту, снаружи — личную. Проверить самому: `git whoami`. Перенастроить: `make identity`.

### Neovim переориентирован

Убрано: Java. Добавлено: рабочий LSP (все серверы были закомментированы —
редактор фактически не работал), автодополнение `blink.cmp`, схемы для YAML/JSON

dockerfile, markdown, gitcommit, diff, go/gomod/gosum, vue, sql, xml.

### Приложения

`Brewfile.apps`: Raycast, Espanso, Hidden Bar, AppCleaner, Keka, а также IINA и
Obsidian — они уже стоят, но перечислены, чтобы новая машина разворачивалась одной командой.

`macos/defaults.sh` — автоповтор клавиш, отключение автозамены кавычек, Finder,
каталог скриншотов, Dock. Применяется отдельно, всё обратимо.

### Инфраструктура

`Makefile` (`link`, `relink`, `unlink`, `core`, `apps`, `macos`, `identity`, `lint`),
`.editorconfig`, `--dry-run` и `--yes` у установщика.

## Этап 2 — решения приняты

### Менеджер паролей — остаёмся на штатном

Отдельный 1Password не нужен. Приложение «Пароли» в macOS закрывает пароли,
passkeys, 2FA и синхронизацию бесплатно и внутри экосистемы.

1Password отличается тремя вещами: CLI, SSH-агент и подстановка секретов в
окружение. Первое и третье при необходимости решаются штатным Keychain:

```zsh
security add-generic-password -a "$USER" -s pg-prod -w      # записать один раз
export PGPASSWORD="$(security find-generic-password -a "$USER" -s pg-prod -w)"
```

Хелперы для этого в конфиг **не добавлены** — при необходимости строчка выше
кладётся в `~/.config/zsh/local.zsh`. Основания вернуться к 1Password: общий с
командой vault или подпись коммитов ключом за Touch ID.

### taskwarrior / timewarrior — отклонено

Не ставим. Сегменты `taskwarrior`, `timewarrior` и `todo` остаются включёнными
в `.p10k.zsh`, но без самих инструментов они просто не отрисовываются.
Почистить список сегментов можно заодно с остальными неиспользуемыми
(`nordvpn`, `ranger`, `nnn`, `xplr`, `perlbrew`, `scalaenv` и прочие).

### ~/.ssh/config — открыто

Единственный нерешённый пункт. Не заведён. Что даёт:

- короткие имена вместо `ssh -i … -p … user@10.20.30.40`;
- `ControlMaster` — одно переиспользуемое соединение, повторные `git fetch`
  и `scp` к тому же хосту идут без нового рукопожатия;
- `ServerAliveInterval` — SSH перестаёт отваливаться по простою;
- `ProxyJump` — базы и поды за бастионом одной командой, включая `scp`;
- разные ключи для личного и рабочего GitHub — стыкуется с идентичностями git.

Ключи в репозиторий не попадают: коммитится только `config`, рабочие хосты
подключаются через `Include ~/.ssh/config.work`.

## Этап 3 — по желанию

| | Зачем |
|---|---|
| CI (shellcheck, `zsh -n`, stow dry-run, gitleaks) | ловить поломки конфига до того, как они доедут до машины |
| `tmux` | сессии переживают обрыв SSH; сплиты iTerm2 — нет |
| `atuin` | одна история команд на обеих машинах, поиск с фильтрами |
| `restic` + `rclone` | бэкап личных данных. Time Machine спасает от смерти диска, restic — от «удалил и заметил через месяц» |
| SSH-подпись коммитов | «Verified» на GitHub тем же ключом, которым делается push |
| `core.fsmonitor` | ускоряет `git status` на больших репозиториях |
| Профили машины (work / personal) | если репозиторий поедет и на рабочий ноутбук |
| Поддержка Linux в `install.sh` | сейчас установщик рассчитан на macOS |
