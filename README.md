# dotfiles

Конфиги для macOS. Ставятся через [GNU Stow](https://www.gnu.org/software/stow/) — каждый компонент отдельно, симлинками.

**Личных данных в репозитории нет.** Имя и почта для git спрашиваются при установке и сохраняются вне git — см. [Идентичности git](#идентичности-git).

## Установка за 5 шагов

```bash
git clone https://github.com/IKulimanov/dotfiles.git ~/dotfiles && cd ~/dotfiles
```

1. **Установить всё:** `./install.sh` — на каждый шаг отвечать `y`
   (`--yes` — без вопросов, `--dry-run` — только показать, что будет сделано).
   Существующие файлы в `$HOME` не затираются, а уезжают в `~/.dotfiles-backup/<дата>/`.
2. **Проверить:** `make check` — покажет ✓/✗ по каждому инструменту, симлинку и плагину,
   и команду для исправления напротив каждого ✗.
3. **Перезапустить шелл:** `exec zsh`.
4. **iTerm2 → Settings → Profiles:** Text → Font → `MesloLGS Nerd Font Mono`;
   Keys → Left Option key → `Esc+`.
5. **Открыть `nvim`** — плагины и LSP-серверы поставятся сами (первый запуск ~1 минуту).

Скрипт можно запускать сколько угодно раз: сделанные шаги он пропускает.
Если что-то не установилось — `make check` скажет, что именно, и что запустить.

### По частям, без скрипта

```bash
make core      # brew bundle --file=brew/Brewfile.core
make link      # stow --no-folding -t ~ zsh git nvim lazygit tig k9s sec
make identity  # имя и почта для git
make help      # остальные цели
```

`--no-folding` здесь принципиален. Без него stow подменяет **каталог** `~/.config/zsh`
симлинком на репозиторий, и всё, что туда пишется — история команд, кеши, Oh-My-Zsh —
оказывается в рабочей копии git. С флагом каталоги остаются настоящими, а симлинками
становятся только файлы.

## Структура

```
zsh/            шелл: Oh-My-Zsh, Powerlevel10k, fzf, zoxide, forgit, модули в conf.d/
git/            настройки, алиасы, delta, nvim как difftool/mergetool (без имени и почты)
nvim/           YAML/k8s, Markdown, логи, Go, git — LSP, автодополнение, форматирование
lazygit/        TUI для git: стейджинг, ветки, rebase
tig/            история, blame и ветки в консоли
k9s/            TUI для kubernetes: поды, логи, рестарт
brew/           Brewfile.core (CLI) и Brewfile.apps (GUI)
macos/          системные настройки через defaults write, Quick Look для Markdown
sec/            dev-секреты в отдельном Keychain: sec add/get/cp/env, экспорт для переезда
test/           тесты sec (make test)
docs/           шпаргалки: cheatsheet.html — весь конфиг (команда cheat), k8s-cheatsheet.html
install.sh      интерактивный установщик; --check проверяет, что всё на месте
Makefile        отдельные операции: make check, link, core, identity, lint
```

## Шпаргалка

```bash
cheat        # открыть в браузере
cheat -t     # текстом в терминале (нужен w3m или lynx)
```

[`docs/cheatsheet.html`](docs/cheatsheet.html) — один файл без внешних запросов: клавиши и
команды zsh, git, forgit, lazygit, tig, Neovim и `sec`, плюс карта файлов конфига. Работает
без интернета и не зависит от того, жив ли сейчас шелл. Нажмите `/` внутри страницы, чтобы
отфильтровать её по подстроке.

Шрифты берутся локальные: моноширинный — тот же `MesloLGS Nerd Font`, которым набран
терминал. Цвета — Catppuccin Latte и Mocha, как в nvim и bat; тема следует за системной.

## Идентичности git

Имя и почта не хранятся в репозитории. `install.sh` создаёт `~/.config/git/identity`
(права 600, в git не попадает), а отслеживаемый `git/.config/git/config` его подключает.

По умолчанию используется **личная** почта. Рабочие аккаунты привязываются к каталогу:
всё, что лежит внутри указанного пути, подписывается своей почтой автоматически.

```
~/proj/pet-project     → личная почта
~/work/service-a       → рабочая почта
~/work/service-b       → рабочая почта
```

Что получается на диске:

```ini
# ~/.config/git/identity            (личная — действует везде по умолчанию)
[user]
	name  = Имя Фамилия
	email = personal@example.com

[includeIf "gitdir:~/work/"]        # всё внутри ~/work/ — рабочее
	path = ~/.config/git/identity.work
```

```ini
# ~/.config/git/identity.work
[user]
	email = work@example.com
```

Аккаунтов можно завести сколько угодно — установщик спрашивает про каждый следующий.
Перенастроить: `make identity`. Проверить, какая идентичность действует здесь: `git whoami`.

## Git в консоли

Три уровня — от быстрого взгляда до полноценного интерфейса.

### 1. Алиасы git — быстрый взгляд

| Команда | Что показывает |
|---|---|
| `git lg` / `gl` | граф последних 30 коммитов: хеш, дата, автор, ветки, сообщение |
| `git lga` / `gla` | то же по всем веткам |
| `git ll` | коммиты с изменёнными файлами и относительной датой |
| `git msg <sha>` | полное сообщение коммита с автором и коммиттером |
| `git hist <файл>` | история файла сквозь переименования, с диффами |
| `git bl <файл>` | blame без учёта пробелов и сквозь перемещения кода |
| `git who [путь]` | кто сколько коммитил |
| `git bra` / `gb` | все ветки таблицей: имя, когда, кто, последний коммит |
| `git bv` | локальные ветки с upstream и отставанием |
| `git search <текст>` | поиск по сообщениям коммитов во всех ветках |
| `git pickaxe <строка>` | коммит, в котором строка появилась или исчезла |
| `git up` | что накопилось в ветке относительно main |
| `git gone` | ветки, чей upstream удалён |
| `git fixup <sha>` → `git ri` | fixup-коммит и autosquash-rebase |
| `git undo` / `git amend` / `git wip` | откат последнего коммита в индекс / добавить в последний / быстрый wip |

Диффы везде через delta: side-by-side, номера строк, `n`/`N` — прыжок к следующему файлу.
`git difftool` и `git mergetool` открывают nvim (трёхпанельный merge с BASE).

### 2. forgit — то же, но интерактивно через fzf

Плагин zsh. Внутри любого списка: `Tab` отметить, `Enter` выбрать, `Ctrl+D/U` листать превью.

| Команда | Что делает |
|---|---|
| `glo` | лог с превью коммита; Enter — открыть diff |
| `gd` | diff по файлам с превью |
| `ga` | добавить файлы в индекс, выбирая из списка |
| `gcb` | переключиться на ветку из списка |
| `gcf` | откатить файл к HEAD |
| `gss` | выбрать и применить stash |
| `gbl` | blame с выбором файла |
| `grh` | убрать файлы из индекса |
| `gclean` | удалить untracked-файлы, выбирая из списка |

### 3. tig и lazygit — полноэкранные

**tig** — читать: история, авторство, поиск. Не нужно ничего помнить, кроме `Enter` и `q`.

```bash
tig                  # история текущей ветки: хеш, дата, автор, граф, ветки
tig --all            # все ветки
tig blame <файл>     # авторство по строкам; Enter — коммит, «,» — предыдущая версия строки
tig status           # что изменено
tig grep <текст>     # поиск по содержимому
tig refs             # ветки и теги; C — checkout
```

**lazygit** (`lg`) — делать: стейджить по строкам, коммитить, переключать ветки, rebase, squash.
`?` показывает все клавиши для текущей панели. Из nvim — `Space g g`.

#### lazygit: разбор истории проекта

Экран разбит на панели, они же цифры. `Tab` или `h`/`l` — соседняя панель,
`j`/`k` — вверх-вниз по списку, `Esc` — назад, `q` — выход.

| | |
|---|---|
| `1` … `5` | статус · файлы · ветки · коммиты · стеши |
| `0` | перевести фокус в большое окно справа, чтобы листать сам diff |
| `+` / `_` | развернуть панель на весь экран и обратно |

**Читать историю — панель `4`.** Граф и порядок `topo-order` уже включены в конфиге,
так что ветка идёт неразрывно, а не вперемешку по датам.

| | |
|---|---|
| `Enter` | файлы коммита, ещё раз `Enter` — изменения по строкам |
| `/` | искать по видимому списку, `n` / `N` — следующее и предыдущее совпадение |
| `Ctrl+S` | фильтр лога: показать только коммиты, где встречается строка |
| `Ctrl+L` | меню лога: включить `--all`, спрятать граф, сменить порядок сортировки |
| `y` | скопировать хеш, сообщение, автора, diff или ссылку на выбор |
| `Ctrl+O` | сразу скопировать короткий хеш |
| `W` | diff между двумя ссылками: отметить одну, потом выбрать вторую |
| `*` | оставить только коммиты текущей ветки |

**Авторство и «когда».** Автор и дата видны в самом списке коммитов.
Чтобы узнать, кто менял конкретные строки: панель `2`, `Enter` на файле, затем `Ctrl+T` —
откроется nvim как difftool. Построчный blame удобнее смотреть в nvim (`Space g b`) или
через `tig blame <файл>`: lazygit про blame не умеет.

**История одной ветки или файла.**

| | |
|---|---|
| `3`, затем `Enter` | коммиты выбранной ветки, не переключаясь на неё |
| `3`, затем `Space` | переключиться на ветку; `c` — по имени, `-` — на предыдущую |
| `lazygit --filter <файл>` | запустить сразу в режиме истории одного файла |
| `lazygit log` | открыться сразу на панели коммитов |

**Менять историю — там же, панель `4`.** Всё это перезаписывает коммиты,
поэтому на общей ветке сначала убедитесь, что её никто не тянул.

| | |
|---|---|
| `r` | переписать сообщение коммита |
| `s` / `f` | склеить с коммитом ниже, с сообщением и без |
| `d` | выбросить коммит |
| `A` | влить то, что в индексе, в выбранный коммит |
| `i` | интерактивный rebase от текущей ветки |
| `t` | revert: обратный коммит поверх |
| `g` | reset на выбранный коммит: soft, mixed или hard |

**Если что-то пошло не так:** `z` отменяет последнюю операцию git, `Z` возвращает.
Работает через reflog, поэтому спасает после неудачного rebase или reset.
Незакоммиченные изменения при этом не восстанавливаются.

## После установки

1. `exec zsh`
2. iTerm2 → Settings → Profiles:
   - **Text → Font** → `MesloLGS Nerd Font Mono` — обязательно, иначе промпт рисует квадраты
   - **Keys → Left Option key** → `Esc+` — для навигации Option+Стрелки
3. `git whoami` в рабочем и в личном репозитории — убедиться, что почты разные
4. Первый запуск `nvim` сам поставит плагины и LSP-серверы

## Что внутри

### zsh

Конфигурация разложена по `conf.d/`, `.zshrc` — только загрузчик.

| | |
|---|---|
| `Ctrl+R` | fuzzy-поиск по истории |
| `Ctrl+T` | поиск файлов (превью через bat) |
| `Alt+C` | переход в каталог (превью дерева) |
| `Option+←/→` | перемещение по словам |
| `↑`/`↓` | поиск по истории с учётом набранного префикса |
| `z <имя>` | умный cd (zoxide) |
| `dot` | перейти в репозиторий dotfiles |
| `v файл:42` | открыть nvim сразу на строке 42 |
| `vf` / `vg <текст>` | выбрать файл / найти по содержимому через fzf и открыть |
| `md файл` | прочитать Markdown в терминале (glow) |

- История — в `~/.local/state/zsh/history`, **не** в репозитории
- `HIST_IGNORE_SPACE`: команда, начатая с пробела, в историю не попадёт — так набирают строки с паролями
- `rm` → `trash` (удаление в Корзину, обратимо). Настоящий `rm` доступен как `\rm`
- Homebrew ставится в начало PATH в `.zprofile` — иначе системный git 2.39 перекрывает brew-версию
- `v` понимает формат `файл:строка:колонка` — тот самый, что печатают `rg`, `grep -n`,
  компиляторы и стектрейсы: строку из вывода можно скопировать и открыть
- `vf` отличается от `Ctrl+T` тем, что не вставляет путь в строку, а сразу открывает nvim
- Локальные настройки и секреты: `~/.config/zsh/local.zsh` (в git не попадает)

### git

`pull.rebase`, `push.autoSetupRemote`, `rerere` с автоприменением, `zdiff3`,
`histogram`, `colorMoved`, `fetch.prune`, `commit.verbose` (diff в буфере сообщения),
`log.follow`, delta с side-by-side, nvim как difftool и mergetool.
Алиасы — в разделе [Git в консоли](#git-в-консоли).

### nvim

Профиль осознанно узкий: **YAML/k8s, документация, логи, Go, личные проекты, git**.
Java здесь не поддерживается — для неё IDEA.

| | |
|---|---|
| `Space f` / `Space s` / `Space b` | файлы / поиск по содержимому / буферы |
| `Space /` / `Space d` | поиск в буфере / диагностика проекта |
| `-` | файловый менеджер в текущем каталоге (oil) |
| `Space tw` | перенос длинных строк — для логов |
| `:Tail` | следить за растущим файлом, как `tail -f` |
| `Space o` | оглавление md-файла (заголовки списком) |
| `Space x` | отметить пункт списка задач: `- [ ]` ↔ `- [x]` |
| `Space t m` | режим таблиц: столбцы выравниваются при наборе |
| `gd` / `gr` / `K` | определение / ссылки / документация (LSP) |

Git — всё на `Space g` (which-key подскажет):

| | |
|---|---|
| `Space g g` | lazygit во всплывающем окне |
| `Space g s` | статус (fugitive): `s` stage, `cc` commit, `=` diff файла |
| `Space g b` | blame всего файла: `Enter` — коммит, `o` — в split |
| `Space g l` / `Space g L` | лог репозитория / коммиты текущего файла, с превью |
| `Space g B` | ветки, `Enter` — checkout |
| `Space g d` / `Space g h` / `Space g H` | diff рабочего дерева / история файла / история репозитория |
| `Space g q` | закрыть diffview |
| `]c` / `[c` | следующий / предыдущий hunk |
| `Space h p` / `Space h s` / `Space h r` | показать / stage / откатить hunk |
| `Space h b` / `Space t b` | кто менял строку / blame рядом с каждой строкой |

- LSP через `vim.lsp.config` / `vim.lsp.enable` (Neovim 0.11+): `gopls`, `yamlls`, `jsonls`, `bashls`, `dockerls`, `marksman`, `taplo`, `lua_ls` — ставятся автоматически через mason
- Treesitter — ветка `main`, парсеры собираются локально (`tree-sitter-cli` из Brewfile)
- YAML со схемами: автодополнение и валидация манифестов k8s, docker-compose, GitHub Actions
- Автодополнение — `blink.cmp`; форматирование — `conform.nvim` (для Go и Lua по сохранению)
- Файлы больше 5 МБ открываются без подсветки, чтобы nvim не подвисал на логах
- Markdown — отдельный профиль в `after/ftplugin/markdown.lua`: перенос строк по словам,
  движение `j`/`k` по экранным строкам, проверка орфографии ru+en (`z=` — варианты замены).
  Файл на диске не переформатируется — перенос только визуальный, иначе дифф в git
  превращается в кашу. Орфография включается, только когда стоит русский словарь:
  один раз выполнить `:set spell spelllang=ru`, и nvim предложит его скачать

### kubernetes

Полная шпаргалка с пошаговым подключением, клавишами k9s и разбором ошибок —
`docs/k8s-cheatsheet.html`, открывается в браузере: `open docs/k8s-cheatsheet.html`.
Ниже — краткая выжимка.

Доступ к кластерам идёт через корпоративный Keycloak (OIDC). `kubectl` сам браузер
не открывает, за это отвечает плагин `kubelogin` (`kubectl-oidc_login`) — он в Brewfile.
Токен обновляется в фоне; логин в браузере нужен только после долгого перерыва.

`~/.kube/config` в репозитории **нет** и быть не должно — это рабочие доступы.
Файл кладётся руками в `~/.kube/config` с правами 600.

Текущий контекст всегда виден в промпте: **прод — белым по красному и с меткой
`PROD:`**, staging — по зелёному, неопознанный кластер — по жёлтому. Цвет виден
до того, как команда набрана, а не после.

#### Три уровня, как и с git

**1. Алиасы — быстрый взгляд.** Вывод `kubectl` подсвечен через `kubecolor`.

| Команда | Что делает |
|---|---|
| `k` | сам `kubectl` |
| `kgp` / `kgpw` | поды / поды с нодами и IP |
| `kgd` / `kgs` / `kgn` | деплойменты / сервисы / ноды |
| `kd <ресурс>` | `describe` |
| `kev` | события кластера по времени — первое, куда смотреть, когда под не поднялся |
| `ktop` | CPU и память по подам |
| `kl` / `klf` | логи / логи с `-f` и хвостом 200 строк |
| `klp` | логи **предыдущего** запуска — когда под уже упал и перезапустился |
| `kex <под> -- sh` | зайти внутрь |
| `kpf <под> 8080:8080` | проброс порта |
| `krr <deployment>` | rolling restart: реплики меняются по очереди, сервис не проседает |
| `krs` / `krh` | статус и история выкатки |
| `kctx` / `kns` | сменить контекст / namespace (без аргумента — выбор из списка) |
| `kmyns` | namespace текущего кластера, где реально есть права — `kubectl get ns` показывает все 80+ |

**2. Логи сразу с нескольких подов — `stern`.** `kubectl logs` умеет только один под.
`stern` держит несколько потоков разом, красит каждый под своим цветом и не отваливается,
когда под пересоздают.

```bash
sl my-service              # все поды, в имени которых есть my-service
sl deploy/my-service       # все поды деплоймента
sls app=my-service         # по label-селектору
sl my-service -s 15m       # начиная с событий 15-минутной давности
sl my-service --no-follow  # разово, без слежения
```

**3. Выбор пода через fzf** — когда имя пода вспоминать лень.

| Команда | Что делает |
|---|---|
| `klog` | выбрать под из списка → его логи с `-f` |
| `kssh` | выбрать под → зайти внутрь (bash, если есть, иначе sh) |
| `kdel` | выбрать под → удалить (деплоймент поднимет новый) |

**4. `k9s` — полноэкранный.** То же, что lazygit, но для кластера: живой список подов
с рестартами и потреблением, события, логи, рестарт в пару клавиш.

| | |
|---|---|
| `:po` / `:deploy` / `:svc` | переключить вид на поды, деплойменты, сервисы |

Хвост логов поднят до 200 строк, длинные строки переносятся, время показывается
рядом с каждой — иначе по JSON-логам и стектрейсам неудобно.

#### Quick Look для Markdown

```bash
make quicklook    # включить: пробел на .md в Finder рисует Markdown, а не текст
make ql-save      # сохранить настройки QLMarkdown в macos/qlmarkdown.plist
```

Рендерит [QLMarkdown](https://github.com/sbarex/QLMarkdown) (`cask "qlmarkdown"`).
Одной установки мало: система узнаёт о расширении только после первого запуска
приложения, поэтому `macos/quicklook.sh` запускает его, включает расширение через
`pluginkit` и сбрасывает кеш Quick Look — иначе уже просмотренные `.md` останутся
текстом.

Настройки (тема, шрифт, расширения Markdown) правятся в самом приложении. Оно в
песочнице, и его plist лежит в групповом контейнере, а не в `~/Library/Preferences`;
`make ql-save` кладёт этот plist в репозиторий, `make quicklook` возвращает на место
при развёртывании новой машины.

Приложение ставит ещё и `qlmarkdown_cli` — рендер `.md` в html из терминала.

### sec — dev-секреты

Пароли БД, токены, SSH-ключи и kubeconfig лежат в отдельном keychain
`~/Library/Keychains/dev.keychain-db`, а не в Apple Passwords: у Passwords нет API,
а `security` из скрипта работает. Команда `sec` (`sec/bin/sec`) прячет длинные вызовы
`security`, даёт автодополнение имён и экспорт для переезда.

```bash
sec init                                   # один раз: создать keychain, задать пароль
sec add pg-staging -a app -n "db1:5432"    # скрытый ввод; или: printf '%s' TOKEN | sec add kafka/token
sec add -f ~/.kube/config k8s/prod         # файл целиком
sec get pg-staging                         # в stdout: psql "postgres://app:$(sec get pg-staging)@db1/app"
sec cp pg-staging                          # в буфер, очистка через 30 с
sec env -- ./gradlew bootRun               # подставить VAR=имя из .secrets в окружение команды
sec ls ssh/                                # список по префиксу, без секретов
sec                                        # fzf: Enter в буфер, Ctrl-O вывести, Ctrl-D удалить
sec export                                 # dev-secrets-ДАТА.age (age -p); passphrase в Passwords
sec import dev-secrets-ДАТА.age            # на новой машине после sec init
```

Имена вида `ssh/id_work`, `k8s/prod` группируются по префиксу в `sec ls` и в `sec get <Tab>`.
Keychain блокируется при сне и после часа простоя; тогда macOS покажет диалог пароля.
Записи видны и редактируются в Keychain Access.app (keychain `dev`).

Переезд: либо скопировать файл `dev.keychain-db` и выполнить `sec init --attach`,
либо `sec export` → `sec init && sec import FILE.age`. Подробности: `sec help`, `sec help add`.

Что не даёт: Touch ID на каждое обращение и защиту от процессов, запущенных от вашего
пользователя, пока keychain разблокирован. Нужно это — 1Password с `op` и SSH-агентом.
